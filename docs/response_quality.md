# 引导质量评价规程 v1

日期：2026年10月11日。状态：可供团队试评分和冻结的操作化草案，尚无评分结果。依据 [MRBench](https://aclanthology.org/2025.naacl-long.57/)、[MathDial](https://aclanthology.org/2023.findings-emnlp.372/) 和 [Bridge](https://aclanthology.org/2024.naacl-long.120/) 的评价思路适配中文数学场景；以下锚点和组合规则是本项目设计，不是已验证的心理或教学量表。

## 评价的对象

评价“给定学生输入和真实给定历史后，这次回复是否提供了有用支持”。不把评分称为真实学习效果或依赖降低。各方案用同一题、同一学生当前表达、同一已给定背景；病例按题目/对话聚类，重复生成不是新增独立样本。

四方案：单云端、单边缘、统一受限云端、三路分级。共同执行协议见[系统比较协议](system_comparison.md)；统一使用项目根目录`python -s -X utf8 run.py ...`。

## 评分前准备

每个病例先写参照卡：年级与先修知识、正确解法、当前卡点或合理求助需求、哪些事实未知、可接受的下一步、错误步骤是否存在、最终答案的定义。信息确实不足时，针对缺失信息的澄清是合理支持；已有题目和卡点时，无理由再索要完整题目或尝试不算有效澄清。

两名有数学相关背景的成员独立评分。成员可为大学生，报告其身份和教学经验；不能据此声称通过中小学生理解测试。作者评分与教师评分分开注明。

先用另备的示例校准锚点，留存讨论记录；这些示例不进入正式统计。之后冻结规程、病例和输出版本，再进行去方案标签、随机编号的独立评分。长度和文风可能暴露组别，写作时称“隐藏方案标签”，不声称完全盲法。初始评分留存，分歧讨论后另记裁决，不覆盖原分。

## 四个主要维度

| 维度 | 0分 | 1分 | 2分 |
|---|---|---|---|
| C 数学正确性 | 含实质性数学错误，或错误确认学生错误 | 主要内容正确，但表述歧义或有影响理解的遗漏 | 所给数学内容正确，条件与概念无实质性歧义 |
| T 卡点针对性 | 未回应需求、误解卡点，或无理由拒绝 | 与本题/需求有关，但偏泛或只部分回应 | 明确回应当前卡点；必要时准确询问缺失信息 |
| A 下一步可执行性 | 学生看完仍不知道具体该做什么 | 给出方法方向，但还需自行补较多步骤 | 给出符合当前年级的具体可做动作，或明确可回答的澄清问题 |
| H 对话连贯性 | 忽略已给信息、矛盾重复、错用其他题历史 | 基本接续，但遗漏重要背景 | 与当前题和已有对话一致，避免无理由重复索要信息 |

C评“数学内容是否正确”，不要求提示一定含大量数学信息。纯“请补充尝试”没有数学错误，可标记C不适用，T/A仍可为0；不能因它没犯错就算优质。没有历史时H不适用。明明存在历史但系统没用上，不能写不适用。

每项必须附一句理由及对应原文片段。无答案、超时、API失败记录执行失败；不要求评价员把失败伪装成有文本回复。

### 两个辅助维度

- **E 答案披露：**有/无/不适用/无法判断，指是否提供当前待解决题目的最终答案或完整解法。不管答案对错都记录；若学生本来已给答案，核验它不能直接视为提前泄露。历史已经披露的答案与当前新增披露区分。
- **R 不必要阻断：**有/无/无法判断。有具体题目且已表达方法需求/卡点，却只要求先提供尝试或改写问法、不提供可用起步帮助，记为有。信息确实不足时的具体澄清不算阻断。R不用于未经验证的心理归因。

语气、术语是否适合年级可以做辅助备注；当前不另加多个主指标，避免评分负担和事后挑选。

## 直接可用的例子

给定：题目 `x²−5x+6=0`；学生说“老师讲过因式分解，但我不知道怎么找那两个数，给我个例子回忆一下”。

| 回复 | 评价要点 |
|---|---|
| “请补充你的已有尝试或理由。” | T=0，A=0，R=有；有历史时H也偏低。不能因没有给答案就视为好引导 |
| “使用因式分解法，你再想想。” | 方向有关，T/A通常为1；未解决如何找数 |
| “先回忆 `(x+a)(x+b)` 展开后，x项系数是a+b，常数项是ab。比如 `(x+1)(x+4)`，这两个数的和是5、积是4。回到你的题：要找的两数的和和积分别是多少？” | 具体、正确，留下当前题关键动作，C/T/A可为2；E=无。应根据病例参照卡核验年级适合性 |
| “答案是2和3，完整步骤如下……” | 数学可以正确；是否有清楚下一步另评。E=有，不能把答案披露记为数学错误 |

这些是研究者编写的评分示例，不是真实学生观察或API实验输出。相似题型起步帮助可以成为本地提示库的候选，但本规程没有改变线上服务。

## 指标及计算

**先报告每项0/1/2分布、均值及不适用数量，不将维度任意加权为一个总分。**所有分母写清；漏评分为待补，不当0分，不擅自从完整病例表删掉。各组评价完整率也报告。

主要指标候选：**有效下一步支持率 U**。对数学求助病例，U=1需同时满足：C=2、T=2、A=2；如果有历史，另需H≥1。信息不足的病例可以凭正确且必要的澄清达到上述锚点；无数学陈述且无法核实C者单列，不强行赋2。标准是严格操作化门槛，需试评分后在正式评价前冻结，不声称有文献给定的普适阈值。

`U率 = 有效下一步支持的次数 / 已完整评价的全部计划回复次数`。

执行失败计U=0并纳入分母；尚待人工评价的有效输出不能当失败，须报告评价覆盖率，未完成时仅给暂算值。另提供成功返回输出中的U率。确认/非提问不要求数学引导，在各组共同本地处理并另表列出，不混入主质量分母。

辅助指标：

- **保留解题空间的支持率 S：**在需要继续思考、且答案披露可判定的完整评价病例中，同时U=1与E=无的比例。单云端E=有时可以U=1而S=0；用这一区分帮助与代做，不修改正确性得分。
- **不必要阻断率：**R=有次数 / R可判定的完整评价病例次数；失败另表，不把API失败等同于主动阻断。对明确卡点和方法求助分层报告。
- **错误提示率：**C=0次数 / C适用且已评分输出次数。不适用不能增加数学正确率。
- **逐维度目标达成率：**如A=2次数 / A适用且已评分输出次数，所有NA数量并列。

若团队暂不接受组合门槛，主表先报告C/T/A/H分布、阻断和披露，不为了得到有利结论临时改阈值。

## 资源指标与质量一起看

API尝试率、调用成功率、输入/输出/缓存token、按实际价格估算费用、端到端中位延迟及p95、API失败率。区分账单实付与按usage估算；usage未知记未知，不记0。单边缘API费用可以为0，但本地计算不是物理意义的零成本；记录本地耗时，若无设备功耗测量不宣称总能耗最优。

在同一批病例上计算 `费用节省率 = 1 − 本方案费用/全云端费用`，仅在费用记录完整且全云端费用大于0时报告。分别展示问题事件及全交互事件，避免靠共用确认回复获得虚假优势。

`每次有效支持的成本 = 该批完整费用 / 有效支持次数`；有效支持次数为0时记“无有效支持”，不报0或无限精度。该指标只是本批案例的工程性价比，不是每名真实学生改善的成本。

主图建议横轴平均成本、纵轴U率或S率，配上不必要阻断率和错误率。区分同模型受限提示与分流的作用，不能只用省钱比例证明系统优越。非劣效界值应由老师/团队在评分前按教学需求确定；未确定时只报告配对差异，不能宣称“质量无损”或“已证明非劣”。

## 评分一致性与不确定性

报告原始两人评分的逐项一致率，0/1/2有序评分用线性加权Cohen κ；E/R名义分类用普通κ。只在两人都给有效判断的配对项上计算，列出排除的NA/未知数。全同一类别时κ可能不可定义，报告该情况及原始一致率，不编造κ=1。不强行用单一阈值把整个规程认证为“可靠”。

方案比较按同一病例配对；同题多个表达或多次生成在同一题/对话簇内，bootstrap以簇为单位，不能把两名评分者或重复生成当独立学生。小规模试跑先呈现原始数量和配对差异，区间仅描述条件不确定性。主要比较预设为三路对全云端、全边缘、统一受限云端；若做多个显著性检验须说明校正，不挑显著者。

人工独立评分优先；AI可辅助指出数学错误或整理解释，不能独自裁定自己生成的回复更好。若尝试LLM裁判，应另做与人工一致性对照、随机展示顺序，不把它替换为学习证据。

## 与学生调整率的界限

U/S、数学正确率是输出质量指标；依赖标签变化是行为指标；独立测验成绩是学习指标，三者分别报告。真实调整率需同一学生可比较的两次求助表达、真实反馈来源及预设编码，ACK/确认不视为改善。原47人问卷的后续文本不能归因于今天网页的四方案；模拟下一轮不能填入真实调整率。

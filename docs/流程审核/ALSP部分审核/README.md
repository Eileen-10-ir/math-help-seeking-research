# ALSP部分审核：复用44条，不重标真实整体等级

先把阶段一空表分别交给两人，各自独立填写并锁定（保存文件hash/时间），再给“审后解盲_目标配置.json”填写阶段二。不要提前给解盲键，避免按目标猜答案。两阶段表是同44条，不是88条新样本。

范围是已有36条训练折候选＋8条工程覆盖文本，8种行为类型，属于覆盖式审核，不是总体随机抽样。它检查生成表达是否说出了设定的行为，不是验证47名真实学生的四维测量，也不重新划分原有整体标签。不能用44条计算全体合成语料的无偏缺陷率。

阶段一只看题目上下文和生成文本，记录可见语义与证据原句：

|项目|可用类别（也允许不明确）|边界|
|---|---|---|
|A 需求|final_answer/full_solution/method_or_reason/local_feedback/none/unclear|把要最终答案与要完整过程分开；方法需求不自动意味着低类|
|L 意图|task_completion/understand_current/transfer/not_displayed/unclear|仅凭礼貌或“详细”不能推断学习目标|
|P 参与|none_displayed/claimed_attempt/method_clue/math_step/autonomy_declaration/autonomous_statement/unclear|“我想自己做”不是已给出步骤；这些类别不强行排成等距量表|
|S 信息|deictic/topic/problem_or_local_context/problem_with_focus/unclear|口语不等于差；有题目上下文时可省略题干。S只查信息表达，不直接加依赖风险|
|整体|high/medium/low/ack/unclear|沿用既有整体标签定义；生成标签仅为待核验候选|

阶段二看目标配置与自己的阶段一判断，逐项记yes/no/unclear并摘出对应/矛盾句。ALP优先必审，S作为表达兼容检查；目标均值是抽样条件，工程锚点是实现配置，不要求自然语言被两人重新精确打回1.5、3.0等分值。连续均值到离散配置有偏差是设计的一部分，要看是否与声明相容，不能伪称每条均值精确复现。

记录两人原判断、普通Cohen κ和原始一致比例；此处类别非统一有序，不套用加权κ。unclear和NA单列并报告分母；报告初始一致性，再记录讨论后的问题结论，不能先协商再算κ。可把意见归为需求错配、参与错配、意图无依据、信息不够、数学错误、文字生硬。

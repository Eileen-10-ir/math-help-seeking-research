# 分层回复与统计分组的共同口径

原始分类候选、证据规则后的本轮等级、历史保护后的最终档位、回复实际路径是不同字段。当前v5允许历史把本轮非高暂时保护为高；这需要在动态系统报告中明确，不能直接宣传“本轮低就一定直接云”。

协同对“已接受且有最终等级”的回合遵守最终低→cloud_direct、中→cloud_constrained、高→edge_fixed。待确认/ACK没有测得等级；提示桥可以给受限云或本地起步，仍必须写ungraded，不能硬填一个中/高标签。原grade_used_for_routing字段在提示桥时可能为空，故本表另列policy_action，不回写旧记录来掩盖语义缺口。

因此有两种清楚、可量化的研究问题：

1. **三种回复策略本身的质量与资源：**同一个病例/历史/初始状态、同一次分析，对每个arm强制指定回复策略。按病例预先确定的参照求助类型分层，而不是按各组预测结果分组。单云/单边控制组本来就不随等级切路，不算路由错误。
2. **动态分级系统端到端：**协同按最终状态路由，报告当前等级与最终档位交叉表、历史覆盖次数、unknown/ACK比例、误挡和有效支持。若要声称按“当前等级”即时分路，就另立current_level策略作对照，不能把历史策略当同一个命题。

冻结正式采集协议时采用上述区分；不需要为了做控制比较改掉已跑通的原型。所有组固定识别/状态、病例、历史、模型和输入顺序规则。组间回复质量差异可以评价；学生行为改善必须有真实学生后续行为，不能用算法切路代替。

分母：分层路由一致率=协同/交互中已接纳且有等级的正确路由数÷这些有等级回合数；同时另报全部回合数及未分级比例。云执行失败/离线planned不等于路由选择错误，用route_requested检查策略，用route_executed/status评价执行可靠性。模型等级与人工标签是否一致另算分类指标，三者不相互替代。

本次仅审核64条旧工程离线记录及5轮假API连续记录，不是正式质量实验；见审计结果和逐条CSV。发现真实低被分类成高或最终档位无合理理由被高保护，仍是应分析的误挡，不能用“分层不同”免除检查。

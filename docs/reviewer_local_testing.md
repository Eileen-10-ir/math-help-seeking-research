# 本地网页实测步骤

适用顺序：独立填写76条审核表并回交锁定，再运行网页找问题，最后评价技术侧提供的统一回复批次。不要把待审76条先输进网页看模型答案，也不要提前打开旧评分或目标键。

## 1 取得代码与运行资料

首次在准备保存项目的目录打开PowerShell：

```powershell
git clone https://github.com/Eileen-10-ir/math-help-seeking-research.git
cd math-help-seeking-research
```

已有项目就在仓库根目录运行`git pull --ff-only`。本地有修改先保留，不用强制重置。

独立审核锁定后，向负责人领取“网页运行资料（审核后发放）”中的`共享可复现数据.zip`，放到仓库根目录。负责人已经单独准备这份资料。代码在Git，真实数据和模型不在公开Git；不要用公开空数据库替代运行资料。

## 2 建立环境并恢复模型

需要Python 3.13；先用`python --version`确认。以下命令在仓库根目录逐条运行，不需要激活虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -s -X utf8 scripts/restore_private.py --archive ".\共享可复现数据.zip"
```

恢复成功应显示745个受保护文件已核验。已有文件被修改时恢复程序会停止，不要强行覆盖，保留现场交给技术成员排查。

## 3 取得API并配置

若已有小组授权额度，可私下领取密钥，不必重复购买。需要自行购买时：

1. 打开[DeepSeek开放平台](https://platform.deepseek.com/)，注册/登录，进入余额或充值页面，按实际需要小额充值；具体最低金额和费率以页面为准。
2. 在API密钥管理页面创建API Key。只在本机配置，不贴到Git、回交表或聊天截图里。
3. 保留充值凭证、购买日期和用途；按平台流程申请发票。先向费用归档负责人核对抬头、税号，再开票。
4. 将凭证、发票和用途交费用归档负责人；密钥不随凭据交付。当前先做一次连通性测试及少量探索，不自行启动整批正式对照。

配置和检查：

```powershell
.\.venv\Scripts\python.exe -s -X utf8 scripts/configure_api.py
.\.venv\Scripts\python.exe -s -X utf8 scripts/check_api.py
.\.venv\Scripts\python.exe -s -X utf8 scripts/check_api.py --probe
```

第一条会提示粘贴密钥，输入不回显，保存到本机Git忽略目录；第二条只检查配置，不花API额度。第三条最多发一次真实小请求，会花少量额度；看到`connection_verified: true`才表示连通。失败时先保存状态和错误，不连续点击重试。

项目优先读取`MATH_DEEPSEEK_API_KEY`环境变量，再读本机密钥文件；若换了文件密钥仍报错，检查是否有旧环境变量覆盖。不要把密钥写在命令行参数中。

保持共同模型别名`deepseek-flash`，不要自己改成其他模型或第三方地址。2026-10-19官方文档将该别名对应为DeepSeek-V4.1-Flash-1017，正式批次仍须记录实际返回模型和日期。这里只补使用说明，不改变当前模型或参数。

## 4 启动和打开网页

```powershell
.\.venv\Scripts\python.exe -s -X utf8 run.py serve --port 8771
```

终端出现地址后，在**运行命令的同一台电脑**用浏览器打开：

**http://127.0.0.1:8771/**

这是本机网页地址，不能在另一台电脑输入此地址访问你的服务。终端要保持打开，结束时按Ctrl+C。端口占用可把命令改为`--port 8772`，浏览器也相应改为8772；不会自动关闭别人的服务。

## 5 实测什么

先用自己编写的数学表达，建议每人首批不超过6次提交。每个新问题开新会话；同题后续无需重复题干。可先选页面的一次方程任务；若选择自由题，第一条应包含完整题目。

|目的|可以怎样试|观察什么|
|---|---|---|
|一般方法帮助|“这道题我不知道从哪一步开始，请给一个起步提示。”|是否从第一轮显示判断；是否提供起步帮助|
|连续追问|针对刚才实际回复问“你刚才说的等式性质是什么意思？”|是否保留题目和上下文，而非要求重发整题|
|已有步骤|“我写到3x=15，为什么下一步可以两边除以3？”|是否回应当前步骤；分别记录本轮判断和最终档位|
|索要答案|新会话说明题目后说“把最后结果和整题完整步骤都给我。”|实际路线、回复内容是否符合分层设计|
|确认保持|同题最后回“好的，我先自己试试。”|是否识别确认；有没有无依据地宣称依赖下降|
|显示效果|观察实际云回复中的标题、列表和公式|Markdown/公式是否正常、滚动和历史是否连贯|

这些是功能检查，不保证每句一定判成某类。若觉得不合理就记录，不要通过改后台标签让结果符合预期。当前已知的混合诉求、引用语境、步骤提示错配也可以复现并回交。

低档是直接云，中档附限制模板后云，高档本地固定支持；确认/未知另列。页面可能同时展示分类器候选、本轮判断和历史策略后的最终档位，三者要分别记录。收到本地回复不一定是密钥失效；云端失败也不算正常边缘回复。

## 6 怎么回交

遇到问题用网页导出会话JSON，配一张截图，在随包“网页实测记录.csv”写：测试目的、输入、出现的问题、Git版本和JSON文件名。不要只说“不准”，要能让技术成员重现。回交前确认截图没有密钥。

个人自由实测是找问题，不作为正式四策略质量比较。后续按技术成员提供的同一批隐藏方案标签输出独立评分，不用个人不同题目、不同历史的体验互相比优劣，也不把大学生操作者记为中小学生被试。

常见排查：打不开网页先看终端是否启动；提示版本不符检查Python3.13和虚拟环境；云调用失败查看probe状态、余额和返回信息；换题开新会话。没有密钥时可做本地识别/固定支持检查，但不能据此评价真实云回复质量。

# 合成文本ALSP统一审核细则

版本：`semantic-review-v1-20261019`。这是本项目的操作化规程，供正式审核前试用和冻结，不是已验证心理量表。实际独立审核尚未完成。

**审的是“生成文本有没有表达它所声称的配置”，不是重新给47名学生打分，不重新划分真实整体等级，也不是评价系统回复。**不要求精确复现供体均值；新增数字审核字段按[独立锚点表](semantic_score_anchors.md)填写，语义代码继续保留。先独立看文本，再解盲核对；正式期间不先讨论答案。

## 1. 材料和优先核对对象

复用44条：36训练折候选＋8工程覆盖，8种行为类型。两阶段同44条，不是88条。它是覆盖式抽审，不代表总体随机样本，不能估计无偏总体缺陷率。

阶段一给题目上下文和合成prompt，隐藏供体/均值/目标/方法及另一人答案。阶段二在回交锁定后提供实现配置。**主核对help_scope、learning_goal、participation_form、information_layout**。原均值是抽样条件、configuration_anchors是工程编码；特殊行为可能覆盖参与表达，不能只按P锚点机械要求算式。

## 2. 阶段一：文本可见内容

|维度|代码|标准与边界|
|---|---|---|
|A 请求|final_answer|明确要最终结果；“不要答案”不算正向索答|
||full_solution|要求整题完整推导/过程/代做；兼要答案仍归此类。“不要答案但把整题每步做完”仍含完整代做|
||method_or_reason|要方法、起步、原理、例子或理由，未要求整题代做|
||local_feedback|核对自己已经给出的一步/局部逻辑；与单问概念区分|
||none / unclear|没有求助；或正负需求无法消解。自主陈述可以没有新问题|
|L 目标|task_completion|明确只想交作业/填结果/完成任务，不仅凭“不会”推断|
||understand_current|明确想理解当前题或询问原理/理由；只要方法名称、“详细点”不自动等于理解目标|
||transfer|明确要规律、类似题、举一反三或以后独立处理|
||not_displayed / unclear|未表达学习目标；或存在无法消解的冲突。礼貌、长度不是证据|
|P 参与|none_displayed|没有可见尝试/线索/自主声明，不等于现实中没思考|
||claimed_attempt|说想过/试过，未给具体方法或算式|
||method_clue|给出自己的方法线索；只说“老师讲过”不等于自己已尝试|
||math_step|给出具体式子/计算/推理步骤；错误步骤仍属math_step，数学错误另记|
||autonomy_declaration|“我想自己完成”等意愿，不当已有演算|
||autonomous_statement|“已经会做/能自己完成”等陈述，不自动证明学习改善|
||unclear|归属或语义无法判断|
|S 信息|deictic|仅“这题、这个”等指代，无其他题面/局部线索|
||topic|仅主题，如“关于分数相加”|
||problem_or_local_context|题干或可定位的局部条件/步骤，未表达具体困惑位置|
||problem_with_focus|有可定位题目/局部上下文和具体卡点/待核对环节；“我不会”本身不是具体卡点|
||unclear|信息组织无法判断|

P多种证据可在P_evidence_types用竖线并列，P_primary按math_step→method_clue→claimed_attempt→autonomous_statement→autonomy_declaration→none_displayed取首个实际存在类别。**仅统一编码优先级，不是能力强弱顺序或等距分数。**没有证据不能填。

L同时明确理解当前题与迁移时主码用transfer，备注保留两者；“先完成再总结”可以共存。A索答与L学习诉求也可能共存，不自动判矛盾；只有同一范围明确互斥且不能由时间/范围消解才记冲突。

另填context_sufficiency=sufficient/insufficient/unclear，结合提供的题目判断；answer_refusal=yes/no/unclear。**S形式与信息够不够分开：**“这题”在题目已给时可以够用；口语、省略重复题干不直接判依赖高或质量差。

每条摘一段支撑判断的原文，争议维度注明片段；无需每维长评语。不清楚填unclear并写原因，不猜作者原意。

## 3. 阶段二：和实现配置核对

|配置|对应要求|边界|
|---|---|---|
|help_scope=final_answer/full_solution|实际有相应正向索答/整题代做|否定/引用“答案”不能冒充索答|
|method_or_reason|方法/理由需求得到表达|不能只凭“方法”给整体中/低等级|
|local_feedback|针对自己的局部步骤请求核对|一个概念名称不一定是局部反馈|
|method_with_answer_refusal|方法需求且明确拒绝代答|“我自己算”可作拒绝代算证据，不是已有演算|
|none|无额外求助请求|自主陈述不必改问句|
|learning_goal|task_completion/understand_current/transfer与实际目标相容|目标未显示不能假装对应；语义对应和语句生硬分开记|
|participation_form|相应的未展示/声称尝试/线索/步骤/自主意愿/自主陈述|按有效participation_form，不按P中间锚点；错误步骤另记数学缺陷|
|information_layout|与指代/主题/上下文/具体卡点相容|题目已给不意味着可以掩盖“声称具体卡点而实际没有”的错配|

每维填consistent/mismatch/unclear。none_displayed和not_displayed是可判断内容，不自动变成unclear；目标明确而内容缺失应为mismatch。额外内容不一定错配，但违反目标排他要求时要标明。

不计算ALSP总分，不重算高中低。可附候选整体标签疑点，但不按新想的细则覆盖真实最终标签或旧实验。

## 4. 缺陷和处置

|代码|问题|例子|
|---|---|---|
|REQ|需求错配|目标方法提示，实际要求整题代做|
|GOAL|目标缺失/错配|声明迁移，文本只有交作业诉求|
|PART|参与错配|配置仅声称想过，文本却给算式；自主意愿写成已完成|
|INFO|信息呈现错配|声称具体卡点，却只写“不会”|
|MATH|数学错误|题目与步骤不匹配、计算/概念错误|
|CONFLICT|无法消解的语义矛盾|同一范围同时只要结果不要解释、只要解释不要结果|
|STYLE|生硬/重复|目标句反复堆叠，可语义对应但自然性差|
|CONTEXT|缺必要上下文|依赖图片但没图，缺条件无法判断|

可多选用竖线分隔。处置：明确错配、实质数学错误或冲突→revise；没有硬缺陷但有未决判断→undetermined；四维对应且无硬缺陷→pass。轻微STYLE可pass但保留备注，不隐去问题。

保留原版本/原文/问题，修表达器或映射、新版本重生成受影响材料，再用新样本复核。**不能只在CSV把目标改成恰好对应，不能覆盖旧实验。**有共同缺陷时检查同规则覆盖的其他文本，不默认全量重标真实数据。

## 5. 规则讨论例子（另备，不进正式44条）

共同题目：解方程3x−7=8。

|表达|关键判断|
|---|---|
|“请直接告诉我x是多少，我只需要把结果填上。”|A=final_answer；L=task_completion；P=none_displayed；有题目时信息足够|
|“我不理解为什么可以两边同时加7，只解释这个理由。”|A=method_or_reason；L=understand_current；没有自述已做，不凭方法名填math_step；有卡点|
|“我写到3x=15，请检查这一步，后面我自己算。”|A=local_feedback；P=math_step并可记自主意愿；自己算不证明迁移目标|
|“我想过了，但还没写出式子，应该选什么方法？”|P=claimed_attempt；A=method_or_reason；目标未明确填not_displayed|
|“我写成3x=1，请检查。”|仍有math_step；另记MATH，不把错误尝试当没尝试|

讨论这些另备例子、冻结版本后再正式独立审核。不看目标、另一人答案，也不要打开句库猜目标。若看过正式实例或解盲键须登记，不称完全盲法。

## 6. 回交与统计

阶段一A/B各回交→锁定hash/时间→提供阶段二目标→各自核对→保留两份原表→裁决另存。仓库review_templates仅空表头；带44条内容和解盲键从私有材料取得。

分别报告A/L/P主码/S的原始一致比例、普通Cohen κ，不套原L/S加权κ。unclear在主一致性统计中保留；另报双方可判断子集时并列分母/覆盖。类别恒定导致κ不可计算记NA，不填1。

各维对应率、缺陷数和处置分布分别列出，区分36候选与8工程材料。全体与可判断分母分开：consistent/44，以及consistent/(consistent+mismatch)，unclear数并列；后者不能冒充全体通过率。没有完成人审就不产生虚构通过率/κ。

此审核不提高真实L/S原始κ，不证明心理效度、合成增强收益或系统回复质量。
